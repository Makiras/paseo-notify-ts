# 通知去向与继承

先在 Host 设置注册接收目标，再在 Host、定时任务、工作区或会话中选择使用哪些渠道。每层可多选，也可关闭通知。

## 选择入口

| 层级     | 入口                                           | 如何保存                             |
| -------- | ---------------------------------------------- | ------------------------------------ |
| Host     | 插件设置 →「Host 默认通知渠道」                | 顶部「保存设置」                     |
| 定时任务 | 插件设置 →「定时任务」栏目                     | 选择任务、调整渠道，再点「保存设置」 |
| 工作区   | 会话输入区「通知」→「工作区通知设置」→「打开」 | 选择立即保存                         |
| 会话     | 聊天输入区「通知」                             | 选择立即保存                         |

命令中心也有相应的 `Notifier` 命令。macOS 用 `⌘K`，Windows / Linux 用 `Ctrl+K`。工作区和会话命令需要处于相应上下文。

## 继承规则

普通会话按 **Host → Workspace → Session** 继承。定时任务生成的会话按 **Host → Schedule → Workspace → Session** 继承。

从当前会话向上寻找最近的明确选择。各层的渠道不会相加：会话明确选择一个渠道，就使用该集合；打开「跟随上级」才使用上一级结果。

| 当前层设置           | 含义                                 |
| -------------------- | ------------------------------------ |
| 开启「跟随上级」     | 动态继承；上级修改后，新通知自动跟随 |
| 关闭继承并选择渠道   | 使用当前层选中的渠道，可多选         |
| 关闭继承且不选择渠道 | 显式关闭当前层通知，不回退           |

Host 没有上级，默认选择为空。下级可以覆盖上级的关闭状态，例如 Host 不发通知，某个会话仍可明确选择开发群。

## 一个例子

Host 默认发到「我的手机」，项目工作区明确选择「开发群」：

- 工作区内普通会话跟随「开发群」。
- 某会话明确选择「运维群」后，只发到「运维群」。
- 该会话恢复「跟随上级」后，重新使用「开发群」。
- 工作区也恢复继承后，普通会话使用「我的手机」；定时任务会话优先跟随任务选择。

## 过滤与变更

选中渠道后，还必须满足渠道启用、通知事件、提供方及工作区过滤。过滤掉的通知不会改发到其他群。默认不通知子代理，AI 复核会话始终排除。

改变选择只影响之后入队的通知，已入队记录保留原渠道。修改接收地址可能取消使用旧凭据的待投递记录，避免旧通知自动发到新群。手动重投失败记录前，先确认接收目标。
