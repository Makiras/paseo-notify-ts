# 设置与凭据

入口：「设置 → 插件 → Paseo Notifier → 通知与自动恢复」。本页解释保存、草稿和凭据管理。

## 一次填写，一次保存

填写渠道名称、通知事件、接收地址及 Token 后，点击顶部「保存设置」。先保存渠道定义、默认去向和普通设置；成功后依次提交有改动的渠道凭据，最后显示整体结果。

只修改凭据，顶部保存按钮同样可用。已有渠道也可使用「保存凭据」单独提交。字段留空不会抹掉已有凭据；更新凭据时应填写完整连接信息。

## 保存失败时

| 情况                   | 结果及处理                                     |
| ---------------------- | ---------------------------------------------- |
| 普通设置未保存成功     | 不提交凭据，保留输入，处理错误后重试           |
| 部分渠道凭据失败       | 成功项清空并收起，失败项保留；顶部列出失败渠道 |
| 再次点击「保存设置」   | 保存普通配置后，只提交仍有草稿的凭据           |
| 请求仍在进行时重复点击 | 不重复提交同一份请求                           |

渠道下「操作结果」显示 URL、Token、请求头 JSON 或连接等具体错误。

## 草稿与缓存

尚未提交的凭据只存在当前页面内存中。保存普通设置、接收其他客户端的普通设置更新、折叠再展开凭据区域，都不会清空它们。

成功保存凭据后，输入清空并收起；界面只显示「已配置」，不从 Host 回填已有密钥。切换 Host、离开页面、移除渠道或点击「放弃修改」会丢弃未保存草稿。

「放弃修改」放弃未保存的普通设置和凭据输入，读取最新普通设置；不会删除已经保存的密钥。

## 多个客户端同时编辑

另一客户端保存设置时，当前页面没有普通设置草稿就更新普通字段。有草稿时会保留，并提示「其他客户端已修改配置」。旧草稿不能直接覆盖新配置。

使用「放弃修改」读取最新设置后重新编辑；如有需要，先记下未保存内容。导入导出只使用已保存配置，也需要先保存或放弃草稿。

## 停用和移除

关闭「启用通知与恢复」停止自动通知和后续自动恢复；「启用渠道」只控制该渠道。显式点击「发送测试」仍是一次手动发送操作。

「移除此渠道」在保存设置后生效，会移除各层对它的选择，并清理对应凭据。原先明确选择它的层级可能变为「关闭通知」，不会自动回退到上级。需要恢复继承时，打开该层的「跟随上级」。
