# 设置与凭据

入口：「设置 → 插件 → Paseo Notifier」。可分别打开「通知管理」「自动恢复与继续」「会话清理」。本页解释保存、草稿和凭据管理。

**Host** 是运行 Paseo 的电脑或服务器；网页、手机是连接它的客户端。**凭据** 是通知平台的连接信息，例如机器人地址、Token 和签名密钥。

聊天输入框另外提供「通知」和「自动继续」两个独立按钮，分别编辑当前会话的渠道与恢复配置；各自的面板均可进入对应工作区设置。自动继续面板需要点击「保存」，通知渠道选择仍即时保存。

## 按栏目浏览

「通知管理」包含渠道、定时任务、消息模板、导入导出、运行状态、版本更新和会话清理；「自动恢复与继续」包含恢复设置和运行状态；「会话清理」直接打开删除列表。

同一入口内切换栏目保留草稿。切换到另一个设置入口前，请先保存当前修改；不同入口共用 Host 配置，并通过配置修订检查避免覆盖其他客户端的更改。

宽屏在页面上方点击栏目标签；手机和窄窗口使用「设置栏目」下拉菜单。每次只展示当前栏目。

| 栏目     | 内容                                                           |
| -------- | -------------------------------------------------------------- |
| 通知渠道 | 注册接收目标、编辑凭据、发送测试、选择 Host 默认渠道           |
| 定时任务 | 为 Paseo Schedule 绑定通知渠道                                 |
| 自动恢复 | 故障类型、重试预算、继续指令及可选 AI 复核                     |
| 通知管理 | 消息模板与 Pattern、示例预览、子代理、回复摘要、投递与保留时间 |
| 导入导出 | 通过剪贴板同步多个 Host 的配置                                 |
| 运行状态 | 查看恢复与投递记录、取消重试、重投通知                         |
| 会话清理 | 查看归档会话、选择并二次确认删除                               |
| 版本更新 | 检查正式 Release、手动启动安装                                 |

「启用通知与恢复」「保存设置」和「放弃修改」是所有栏目共用的操作。保存会提交所有栏目的修改；放弃修改也作用于所有栏目。有字段错误时，顶部「前往修改」会打开第一个错误所在的栏目和渠道。

## 编辑渠道

在「通知渠道」选择「新渠道平台」，点击「添加渠道」。新渠道会自动进入编辑状态。在「编辑渠道」选择已有接收目标，每次显示一个渠道的表单；同一平台可以添加多个目标。渠道列表中的「凭据待保存」提示连接信息仍未提交。

当前渠道下方是「Host 默认通知渠道」，用于勾选默认接收目标。这里的默认通知选择与正在编辑哪个渠道互不影响。

## 一次填写，一次保存

填写渠道名称、需要接收的通知类型、接收地址及 Token 后，点击顶部「保存设置」。这会一起保存所有栏目的修改和新填写的连接信息，不需要分别保存每个栏目。

只更换地址或密钥时，顶部保存按钮同样可用。已有渠道也可使用「保存凭据」单独保存连接信息。只修改名称、通知模板等设置时，原有连接信息会保留；如果要更新连接信息，请重新填写完整内容，保存时会整份替换旧值，未重新填写的可选密钥不会自动保留。

看到保存成功后，可以直接点「发送测试」，无需刷新页面。测试使用已经保存的设置；如果又修改了内容，请先保存再测试。连接有问题时，可查看渠道下的「操作结果」或「运行状态」。

## 保存失败时

| 情况                   | 结果及处理                                     |
| ---------------------- | ---------------------------------------------- |
| 普通设置未保存成功     | 不提交凭据，保留输入，处理错误后重试           |
| 部分渠道凭据失败       | 成功项清空并收起，失败项保留；顶部列出失败渠道 |
| 再次点击「保存设置」   | 保存普通配置后，只提交仍有草稿的凭据           |
| 请求仍在进行时重复点击 | 不重复提交同一份请求                           |

渠道下「操作结果」显示 URL、Token、请求头 JSON 或连接等具体错误。

## 草稿与缓存

尚未保存的输入只暂存在当前页面。切换栏目、切换渠道或收起再展开填写区域，都不会清空它们。

连接信息保存成功后，输入框会清空并收起，这是正常的保密处理，不代表地址或密钥丢失。页面会显示已保存状态，仍可发送测试。切换 Host、离开或刷新页面、移除渠道、点击「放弃修改」会丢弃未保存内容。

ntfy 和 Telegram 的服务根地址在输入时明文显示；含密钥的 Webhook / Bark 地址、Token、签名密钥和接收目标仍遮掩。

「放弃修改」放弃未保存的普通设置和凭据输入，读取最新普通设置；不会删除已经保存的密钥。

## 多个客户端同时编辑

另一客户端保存设置时，当前页面没有普通设置草稿就更新普通字段。有草稿时会保留，并提示「其他客户端已修改配置」。旧草稿不能直接覆盖新配置。

使用「放弃修改」读取最新设置后重新编辑；如有需要，先记下未保存内容。导入导出只使用已保存配置，也需要先保存或放弃草稿。

## 停用和移除

关闭「启用通知与恢复」停止自动通知和后续自动恢复；「启用渠道」只控制该渠道。显式点击「发送测试」仍是一次手动发送操作。

「移除此渠道」在保存设置后生效，会移除各层对它的选择，并清理对应凭据。原先明确选择它的层级可能变为「关闭通知」，不会自动回退到上级。需要恢复继承时，打开该层的「跟随上级」。
