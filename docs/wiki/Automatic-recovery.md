# 自动恢复

自动恢复在原会话发送继续指令，让任务从临时中断处继续。它默认关闭，与通知投递重试是两件事。

## 会话与工作区设置

聊天输入框有两个独立入口：「通知」选择接收渠道，「自动继续」控制故障后的恢复。两套继承设置互不影响。

点击「自动继续」可查看当前开启状态及设置来自 Host、Workspace 还是 Session：

1. 默认开启「跟随上级」：Session 跟随 Workspace，Workspace 未单独配置时跟随 Host。
2. 关闭「跟随上级」：以当前生效参数作为起点，单独配置当前范围。可关闭「自动继续」，或展开「重试参数与 AI 复核」修改异常类型、预算、继续指令及复核。
3. 点击「保存」后生效。重新打开「跟随上级」并保存，会移除本范围的覆盖，以后跟随上级变化。

这是整份恢复配置的继承；单独配置后，所有恢复参数都使用本范围保存的值，不再逐项跟随 Host。工作区关闭时，单独开启的会话仍可恢复；插件总开关关闭时，所有范围均停止自动继续。

会话面板底部可打开「工作区自动继续设置」。也可在 Command Center 搜索「Notifier：会话自动继续设置」或「Notifier：工作区自动继续设置」。Host 默认值在插件「自动恢复与继续」入口配置。

修改后先保存再关闭面板；关闭面板会丢弃未保存草稿。其他页面同时更新设置时，本页会保留草稿并提示重新读取，避免覆盖新值。修改其他会话，或修改当前范围已覆盖的上级参数，不会取消本会话等待中的恢复。关闭本会话实际使用的恢复设置，会取消后续重试，不中止已经运行的 AI。

这些设置只配置恢复行为，不会立即运行任务，也不会重新激活过去已结束的恢复计划。

## 开启与适用异常

进入 Host 插件设置 →「自动恢复与继续」→「自动恢复」，开启「自动继续」，选择异常类型和预算，点击「保存设置」。

| 中断                                 | 行为                         |
| ------------------------------------ | ---------------------------- |
| 网络故障、连接断开                   | 网络恢复开关启用时重试       |
| 服务繁忙、容量不足、临时服务端错误   | 服务繁忙开关启用时重试       |
| 请求限流                             | 限流开关启用时等待后重试     |
| 额度耗尽、上下文已满                 | 通知人工处理                 |
| 安全策略 / cyber 拦截                | 通知人工处理，不自动反复提交 |
| 未识别错误                           | 停止自动恢复并通知           |
| 用户取消、权限等待、会话或工作区关闭 | 取消后续恢复                 |

三个可恢复类别默认启用，但只有「自动继续」开启后才生效。

OpenCode 自带的模型请求重试属于另一层，不受本页开关控制。要在 OpenCode 内部阻止明确的 cyber 拒绝重试，可单独安装 [OpenCode cyber 拒绝保护](OpenCode-cyber-guard.md)。

## 预算

| 设置             | 默认                       | 用途                                                 |
| ---------------- | -------------------------- | ---------------------------------------------------- |
| 最大重试次数     | 5 次                       | 同一故障恢复计划最多提交几次继续指令                 |
| 恢复时间上限     | 30 分钟                    | 包括等待和复核的总预算                               |
| 初始等待         | 10 秒                      | 第一次恢复前的退避基准                               |
| 两次重试最多间隔 | 300 秒                     | 连续失败时逐渐延长等待；服务要求等得更久时按要求等待 |
| 继续指令         | 检查已有进度，从中断处继续 | 提交给原会话的固定文本                               |

等待逐渐增长并加入少量随机抖动。同一故障预算跨自动轮次和重启保留，重启不会把次数清零。

## 停止条件

恢复依据最新执行结果及当前运行状态。提交前检查会话可用、处于错误状态、没有正在运行的回合或待确认权限。恢复检查不读取聊天历史，不比较历史内容，也不要求找到用户消息；长会话、摘要或历史分页缺项不会阻止恢复。

- 新执行开始后，旧等待计划停止；新执行如果再次失败，会按新结果重新判断。修改任务内容不会永久关闭自动恢复。
- 正常完成、当前正在运行或初始化时，不额外发送继续指令。
- 会话状态请求失败时暂停，并明确显示“无法核对会话状态”；不会假定已运行，也不会误报“内容有变”。
- 只有启用 AI 复核时才读取一页有限摘录；复核结束后再检查执行状态。
- 发送回执不明确时暂停，避免重复提交。重复的执行事件不会重新启动同一个恢复计划。

升级不会自动重新激活此前已经取消或暂停的计划。若旧版误取消了长会话恢复，在更新后手动继续一次；后续新的可恢复故障会使用修正后的判断。

## 取消与通知

在会话恢复卡片点「取消后续重试」，或在 Host「运行状态」点「取消重试」。这只停止后续自动操作，不中止已在运行的 AI 任务；停止当前执行请使用 Paseo 自身的停止操作。

恢复成功发送「恢复后完成」。无法继续或预算耗尽时显示原因，并按渠道选择发送失败或需要处理的通知。
