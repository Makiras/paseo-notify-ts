# 运行状态与排错

Host 配置页底部的「运行状态」展示最近的恢复任务和通知投递，打开页面后约每 5 秒刷新，也可手动刷新。会话界面还会展示恢复卡片。

## 状态含义

| 恢复状态        | 含义                                       |
| --------------- | ------------------------------------------ |
| 等待 / 复核中   | 正在退避，或等待独立 AI 判断               |
| 派发中 / 运行中 | 已准备发送继续指令，或原会话正在继续       |
| 已暂停          | 会话变化、复核异常或回执不确定，需人工核对 |
| 预算耗尽        | 达到次数或总时间上限                       |
| 已完成 / 已取消 | 恢复结束，或停止后续自动尝试               |

| 投递状态 | 含义                                   |
| -------- | -------------------------------------- |
| 等待发送 | 排队或等待下一次重试                   |
| 已发送   | 平台确认受理；不保证设备已经显示       |
| 发送失败 | 不可恢复错误或次数耗尽，可手动重试     |
| 已取消   | 渠道、凭据或插件配置变化，旧投递已停止 |

取消恢复只停止后续重试，不停止已经运行的原任务。重试通知只重发该条消息，不会重新运行 AI。

## 常见问题

| 现象                          | 先检查什么                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 测试成功，任务结束却没有消息  | Host 默认是否选中渠道；工作区、任务、会话是否覆盖或静音；渠道事件过滤是否允许        |
| 新渠道填写 URL 后要保存两次   | 顶部「保存设置」已支持先配置后凭据的一次操作；旧界面需更新插件。失败的凭据输入会保留 |
| 保存显示配置冲突              | 其他客户端修改了同一 Host；保留草稿，核对后放弃修改并重填，不会强行覆盖              |
| 重启后恢复暂未继续            | 打开设置页或原会话，让插件取得宿主 SDK 并核对会话；等待状态不是自动重新开始预算      |
| 网络问题没有自动继续          | 确认自动恢复及对应类别已开启，查看分类、预算、会话边界和 AI 复核结果                 |
| security / cyber 中断没有继续 | 安全拦截不属于自动恢复范围，复核也不会改变这一规则                                   |
| 定时任务找不到                | 在正确 Host 创建 Schedule，刷新任务列表；Heartbeat 使用原会话路由                    |
| 工作区配置入口找不到          | 打开任意该工作区会话，点输入区「通知」，再点「工作区通知设置 → 打开」                |
| 平台错误码 / HTTP 错误        | 检查凭据、目标、Bot 权限和 Host 网络；外部响应中的秘密不会原样显示                   |
| 更新回执中断                  | 检查所选工作区的 `Notifier update` 终端及 Paseo 插件状态，再重新打开设置确认版本     |

## 存储或初始化异常

运行记录无法读取、数据目录不可写或重复实例持有锁时，插件会停止相关自动操作并显示错误。先检查目录权限、现有进程和文件完整性，不要通过删除运行记录来反复重置预算。

需要定位宿主错误时，在目标 Host 查看插件日志：

```sh
paseo plugin logs paseo-notifier
```
