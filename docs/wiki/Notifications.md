# 通知事件与内容

通知报告会话结果与需要处理的状态。接收目标由[通知去向与继承](Notification-routing.md)决定。

## 事件

| 界面名称     | 标识         | 何时发送                                   |
| ------------ | ------------ | ------------------------------------------ |
| 任务完成     | `completed`  | 普通会话轮次成功结束                       |
| 恢复后完成   | `recovered`  | 自动恢复后，原任务轮次成功结束             |
| 任务失败     | `failed`     | 无法恢复、预算耗尽或恢复暂停等情况         |
| 需要处理     | `blocked`    | 安全策略、额度、上下文等需要人工处理的中断 |
| 等待权限确认 | `permission` | 会话请求权限，需要回到 Paseo 处理          |
| 测试通知     | `test`       | 点击渠道的「发送测试」                     |

每个渠道默认接收前五类事件，可以分别关闭。自动恢复期间合并中间失败通知，最终完成或停止恢复时再报告。

## 内容与摘要

默认包含事件类型、任务标题、简短状态、会话 ID、提供方、时间；有恢复尝试时包含次数。

「通知管理 → 附带最终回复摘要」可附上最终回复的截取内容。默认关闭，默认上限 600 字符，可设 80–2000。这里只截取已有回复，不额外调用 AI 总结。

同一栏目可编辑通知标题、正文模板，使用内置占位符和自定义正则补全信息；页面提供默认模板、说明、工单号 / 链接示例和实时预览。操作见[消息模板与 Pattern](Message-templates.md)。

不同平台会进一步截断超长文本。AI 复核理由留在 Paseo 恢复卡片与运行状态中，不直接附到外部通知。

## 会话范围与过滤

默认只处理主会话。开启「包含子代理」可处理普通子代理事件，插件自己的 AI 复核会话仍排除。

通知必须满足渠道启用、事件、提供方和工作区过滤。测试按钮直接检查连接，不代表实际路由条件都已满足。

## 投递与重试

同一渠道按顺序发送，不同渠道互不阻塞。网络错误、HTTP 408 / 429 / 5xx 和已识别的平台临时错误会重试，并遵守可识别的等待提示。

「通知最多发送次数」默认 5 次，可设 1–12。永久错误停止重试。修正配置后，在「运行状态」找到失败记录，点「重试发送」。它重投原通知，不会重新执行 AI 任务。

回执丢失可能造成重复通知。通用 Webhook 接收端可使用事件 ID 去重，详见[Webhook 协议](Webhook-protocol.md)。

## 测试通知

「发送测试」立即联系真实接收目标。成功表示平台接受了测试请求；测试不进入普通自动投递重试队列。失败时查看渠道的「操作结果」。
