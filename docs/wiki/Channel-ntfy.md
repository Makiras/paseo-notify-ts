# ntfy

在 ntfy 客户端订阅一个 Topic，然后让插件向同一个服务和 Topic 发布消息。支持公共服务和自托管服务，接口见 [ntfy 发布文档](https://docs.ntfy.sh/publish/)。

| 界面字段     | 填写方法                                                   |
| ------------ | ---------------------------------------------------------- |
| 服务根地址   | 默认 `https://ntfy.sh`；自托管填写服务根地址，不附加 Topic |
| Topic        | 1–128 个英文字母、数字、下划线或连字符                     |
| Bearer Token | 服务要求身份认证时填写访问 Token                           |

插件向根地址发送 JSON，Topic 放在请求体中。客户端订阅的服务地址和 Topic 必须完全对应。

服务根地址是连接入口，输入时明文显示，便于检查域名；不要把 Token 或 Topic 拼进这个字段。Bearer Token 继续遮掩。未设置访问控制的 Topic 可能被知道名称的人订阅或发布，因此 Topic 输入也默认遮掩。依据：[ntfy Topic 说明](https://docs.ntfy.sh/publish/#picking-a-topic)。

公开服务的普通 Topic 名称本身不等于访问控制；需要限定接收者时使用服务提供的认证与权限配置。插件支持 Bearer Token，不提供账号密码登录界面。

保存后按[公共步骤](Channels.md)选择路由并测试。常见问题是把 `https://ntfy.sh/topic` 填成根地址、Topic 与手机订阅不一致，或者 Token 没有发布权限。

凭据写入成功后，「发送测试」即可使用，渠道状态会自动刷新，无需退出重进设置页。顶部「保存设置」会先保存渠道定义，再提交凭据；仍在保存时，测试暂不可用。按钮下方会提示缺少渠道定义还是连接信息。
