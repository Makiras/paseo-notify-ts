# 版本与更新检查

入口是 Host 配置页的「版本更新」栏目。检查和安装针对当前 Host；多台 Host 分别操作。

## 自动检查

「打开设置时自动检查更新」默认开启，修改后点击顶部「保存设置」。开启时在打开配置页时检查本仓库的最新正式 GitHub Release，成功结果缓存 6 小时；关闭后仍可点击「检查更新」。它不在后台定时下载代码。

只接受 `v主版本.次版本.修订号` 的正式发布，跳过草稿、预发布和分支提交。版本按数字比较，不会把旧版本提示为升级。检查失败保留上次结果并显示错误，暂时禁用安装；通知和自动恢复继续工作。手动检查也有至少 1 分钟间隔，避免反复请求 GitHub。

界面显示插件版本；可以确认官方 Git 安装来源时，还显示当前提交。GitHub 检查只发送公共 Release 查询，不发送渠道配置、凭据或会话内容。

## 从页面安装

1. 保存或放弃所有未保存设置和凭据。
2. 点击「检查更新」，阅读目标 Release 的发布说明。
3. 点击「选择工作区」，选择用于显示安装输出的工作区。
4. 点击「安装 vX.Y.Z」。

插件在该工作区创建 `Notifier update vX.Y.Z` 终端。终端由 Paseo 管理，调用 Host 上的官方 CLI；插件重载后安装仍可继续。工作区只是安装输出的位置，更新的是整个 Host 上的插件。

安装前校验来源并把 Release 标签解析为固定提交；随后使用该提交执行更新，避免普通更新跟随默认分支。开始后点击「打开工作区」查看终端。终端显示 `UPDATE SUCCEEDED` 后重新打开设置，核对版本和提交。页面出现“已创建更新终端”只表示启动成功。安装结束后终端保留结果，按 Enter 或关闭终端即可退出。

页面安装需要默认 ID `paseo-notifier`、从本仓库直接 Git 安装，以及 Host 的 PATH 中可直接执行的 Paseo CLI。本地目录、压缩包目录、npm、Registry、修改过 ID、其他仓库来源不属于页面安装支持范围。Windows `.cmd` 启动器不能由此入口执行；使用 Host 终端手动更新。

## 手动命令与失败处理

页面提供带有当前 Host `--home` 和目标标签的更新命令，可直接复制到该 Host 的终端。远程连接也可以使用[安装与更新](Installation-and-updates.md)中的 `--host` 方式。

更新准备或激活失败时，由 Paseo 保留或恢复旧安装。CLI 超时、断连或回执不确定时，先查看终端和宿主插件状态，再决定是否重试；不要根据网页断开直接再次点击安装。重新打开设置可以重新读取状态。

自动恢复预算、投递队列和凭据在插件私有目录中，不会因为正常更新重新开始。更新重载期间的事件边界与普通 Reload 相同，见[宿主能力与限制](Host-limitations.md)。

## 发布机制

项目使用语义版本号。每次合入 main 会运行检查并提供 CI 安装包；只有推送 `vX.Y.Z` 标签且发布检查通过，才生成正式 Release、`.tgz`、SHA-256 校验文件和包含提交号的 `release.json`。普通 main 构建不是正式发布，也不会被本页提示为新版。

维护者操作见[开发与 CI](Development-and-CI.md)。Paseo 自带网页管理目前没有远端更新审阅入口；本插件的安装按钮使用官方 CLI 完成操作。依据：[Paseo 插件管理说明](https://paseo.sh/docs/plugins/reference#cli-reference)。
