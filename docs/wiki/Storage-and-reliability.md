# 存储与可靠性

插件不维护会话数据库。会话内容与任务历史由 Paseo 管理；插件保存执行自动化所需的少量运行记录，防止重启后丢失预算、重复继续或丢掉已排队通知。

## 数据位置

优先使用 `PASEO_NOTIFIER_STATE_DIR`，否则为 `$PASEO_HOME/notifier`，没有设置 Paseo Home 时为 `~/.paseo/notifier`。

| 文件 / 位置                | 保存内容                                                            |
| -------------------------- | ------------------------------------------------------------------- |
| Paseo 的 Host 插件设置     | 渠道定义、过滤、继承绑定、恢复与复核参数、更新偏好                  |
| `credentials.json`         | Webhook URL、Token、签名密钥、目标 ID 和自定义请求头                |
| `operations.json`          | 恢复预算与阶段、执行与消息 ID、复核状态与清理记录、投递队列、去重键 |
| `owner.lock` / `reap.lock` | 单实例占用和锁恢复协调信息                                          |

目录使用 `0700`，私有文件使用 `0600`。文件权限是隔离措施，凭据本身没有加密；备份和迁移时应把该目录作为敏感数据处理。

## 为什么保存恢复记录

一次恢复可能跨越多次自动继续和插件重载。只在内存计数会让重启重置预算，还可能在“继续指令已发送、回执未收到”时重复发送。插件持久化原预算、发送意图和消息标识，遇到无法确认的状态暂停，由用户检查。

这不是通过保存全部会话来恢复 AI。普通恢复仅核对 Paseo 的执行状态，启用 AI 复核时才读取有限历史摘录；不把完整对话复制进自己的数据库。启用最终回复摘要时，待投递通知中会包含该摘要。独立复核会话的历史仍由 Paseo 保存。

## 写入与重启

运行记录采用串行事务、临时文件写入、同步与原子重命名；实例锁阻止同一数据目录被重复运行。损坏文件或无法确认锁状态时停止自动操作，不创建一个空状态来重置预算。

重启后已排队的通知可以继续投递。恢复原任务需要首次宿主回调或 RPC 提供 SDK 连接，之后再次核对会话。重启时尚未结束的 AI 复核会暂停，并在取得连接后清理已记录的复核会话，不会悄悄重新开启一轮判断。

## 重复与不确定回执

HTTP 请求可能已被平台处理，但回执在网络中丢失，因此外部消息不能保证严格只到达一次。通用 Webhook 提供固定事件 ID 和幂等请求头，接收端可去重。

已入队的投递保留原渠道；修改路由不会改写旧投递。修改凭据会取消使用旧凭据摘要的待投递记录，避免把旧通知自动发往新目标。手动重试失败通知会使用该渠道当前凭据，可能重复，请先核对目标。

## 保留与清理

已结束记录默认保留 7 天，可调为 1–30 天。活跃恢复和待投递记录不会仅因超过保留天数而删除。实现另有数量上限：活跃恢复 1000、投递记录 2000、去重记录 5000；容量不足时会明确停止相应操作。

移除插件不会自动删除上述私有目录。确需清理时先停止插件并备份；删除运行记录会丢失预算与去重信息，不能作为日常重试手段。

相关：[自动恢复](Automatic-recovery.md) · [通知事件与内容](Notifications.md) · [Webhook 协议](Webhook-protocol.md)

v0.4.1 起不再保存或比较恢复用的历史指纹。旧运行记录可以直接读取：保留次数、时间预算和已取消状态，忽略旧指纹字段。通知凭据摘要仍用于避免旧通知发到被更换的接收地址，与会话恢复无关。

## 删除后的配置

通过插件确认删除会话后，客户端核对会话确实不存在，再移除该会话的通知选择和自动继续覆盖。清理通过 Paseo 配置修订号保存；并发冲突时重新读取，不覆盖其他页面的新设置。清理失败会单独提示「配置待清理」，可重试清理，不重复删除会话。渠道、凭据、Host 默认值、工作区和其他会话的绑定都保留。

归档不是删除，不清理绑定。Paseo 当前未提供专用删除回调，因此插件不能保证外部删除或客户端中途断开后立即清理残留绑定。残留只是少量无目标的配置项，不会用于其他新会话。已删除定时任务仍可在「定时任务」栏目以“任务不在列表中”的绑定项找到，打开「跟随上级」并保存即可移除。列表读取失败、分页缺项、暂停和执行结束不会触发自动清理。

运行记录与配置分开：删除前停止后续恢复，历史运行记录继续按保留期清理；删除绑定不删除注册渠道或清空整个运行日志。
